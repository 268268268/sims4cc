## Этап 0 — Безопасность и гигиена (обязательный минимум)

Цель: закрыть реальные дыры до любых новых фич. Все правки малорисковые.

### 0.1 Обновить Electron 31 → актуальный мажор — **L, критично**
- Ветка 31 не получает патчи Chromium с начала 2025, а приложение рендерит
  удалённый контент (Tumblr/Patreon/CurseForge) и открывает окна логина.
- Файлы: `package.json`, проверка `webUtils.getPathForFile` (стабильный API),
  `protocol.handle`, `net.fetch` с `session:` — всё это живо в новых версиях.
- Приёмка: `npm run dev` работает; логин Patreon, скачивание с CF, drag&drop,
  modimg-превью — вручную проверены.

### 0.2 `sandbox: true` для главного окна — **S**
- Preload использует только `contextBridge`/`ipcRenderer`/`webUtils` — работает в песочнице.
- Файл: `src/main/index.js` (`createWindow`, сейчас `sandbox: false`).
- Приёмка: все IPC-вызовы и drag&drop работают.

### 0.3 Guard навигации окна — **S**
- В `createWindow()`: `setWindowOpenHandler` → `deny` + `shell.openExternal` для https;
  `will-navigate` → `preventDefault` (кроме ELECTRON_RENDERER_URL в dev).
- Защищает от увода окна ссылкой из описания мода.

### 0.4 Валидация `shell:openExternal` — **S**
- Файл: `src/main/index.js:483`. Пропускать только `^https?:`.

### 0.5 CSP в renderer — **S**
- Файл: `src/renderer/index.html`. Meta-тег:
  `default-src 'self'; img-src https: data: modimg:; style-src 'self' 'unsafe-inline'; script-src 'self'`
  (в dev electron-vite может требовать послаблений — проверить оба режима).

### 0.6 Шифрование CF API-ключа через `safeStorage` — **M**
- Файлы: `src/main/services/configStore.js` (+ миграция: если в config.json лежит
  открытый ключ — зашифровать и перезаписать), `curseForgeClient.getApiKey()`.
- Приёмка: старый конфиг мигрирует прозрачно; поиск CF работает.

### 0.7 Фикс управляющих символов в названиях модов — **S**
- Виден на скрине: карточка «…壁挂置物架\n» с литеральным `\n`.
- Файлы: `src/main/services/packageMeta.js` (STBL-имя), `localModScanner.deriveName`.
  Стрипать `[\x00-\x1F]` и экранированные `\n`/`\r`/`\t`, схлопывать пробелы.
- Приёмка: после Rescan имя чистое (кэш метаданных инвалидировать по версии кэша).

### 0.8 Убрать/загейтить DEBUG-логи — **S**
- `curseForgeClient.js` логирует каждый запрос и ключи ответа. Обернуть в
  `if (process.env.CF_DEBUG)` или удалить.

### 0.9 `backgroundColor` окна под тему — **S**
- Сейчас `#1a1a2e` (сине-фиолетовый) при тёмно-зелёной теме — цветная вспышка
  при запуске. Заменить на фоновый цвет темы.

## Этап 1 — Производительность

### 1.1 Миниатюры для сайдкар-картинок — **M, самый заметный выигрыш**
- Авторские preview.png бывают 4–8 МБ; грид грузит их полноразмерно.
- Решение: в обработчике `modimg://` (или на этапе скана) ужимать до ~400px через
  `nativeImage.resize()` и класть в существующий thumb-cache (`dbpfThumbnail.js`),
  ключ — путь+mtime. Оригинал остаётся для Lightbox.
- Приёмка: холодная загрузка грида на библиотеке с тяжёлыми PNG заметно быстрее;
  Lightbox показывает оригинал.

### 1.2 Виртуализация грида Local Mods — **M**
- Библиотеки симеров — тысячи файлов; сейчас все карточки в DOM.
- Шаг 1 (дёшево): CSS `content-visibility: auto` + `contain-intrinsic-size` на карточке.
- Шаг 2 (если мало): react-window / виртуальные ряды.
- Файл: `src/renderer/src/pages/LocalMods.jsx`.
- Приёмка: плавный скролл на 5000+ карточек (сгенерировать тестовую папку).

### 1.3 Параллельный обход папок в сканере — **S**
- `walkDir` рекурсивен последовательно (`localModScanner.js:74`). Собирать
  подпапки и обходить их через `Promise.all`.
- Приёмка: `durationMs` холодного скана на большой библиотеке снижается.

### 1.4 Ревизия IPC-пейлоадов — **S, по желанию**
- `localMods:scan` возвращает весь массив DTO; при 10k модов это мегабайты.
  Если появятся жалобы — отдавать чанками или дельтой. Пока просто замерить.

## Этап 3 — Новые возможности

### 3.1 Автоопределение папки Mods при первом запуске — **S/M**
- Проверить `%USERPROFILE%/Documents/Electronic Arts/The Sims 4/Mods`
  (+ локализованные варианты «Документы»), предложить одной кнопкой.
- Файлы: `configStore.js` или новый `modsFolderDetect.js`, `Settings.jsx`,
  онбординг-экран при пустом конфиге.

### 3.2 Детектор конфликтов модов — **L, киллер-фича**
- DBPF-парсер уже есть (`dbpfParser.js`). Собрать по каждому `.package`
  множество TGI (type/group/instance) ресурсов, найти пересечения между
  разными модами, показать группы конфликтов (какой мод перекрывает какой).
- UI: вкладка/фильтр «Conflicts» в Local Mods, бейдж на карточке.
- Осторожно с ложными срабатываниями: одинаковые тюнинг-инжекторы и
  общие библиотеки — вести whitelist известных безопасных пересечений.
- Приёмка: два мода, правящих один ресурс, детектятся; скан конфликтов
  кэшируется и не replaces обычный скан.

### 3.3 Мультивыбор и bulk-операции — **M**
- Checkbox-режим в Local Mods: выделить N → Enable/Disable/Delete одним действием.
- Main-часть уже готова (`toggleEnabled`/`delete` по одному) — цикл + прогресс.

### 3.4 Профили (наборы модов) — **L**
- Именованные наборы (=список путей + желаемое enabled-состояние), быстрый
  свитч: «геймплей», «CAS», «скриншоты». Хранить в userData (`profiles.json`).
- Экспорт/импорт списка модов (share/бэкап).

### 3.5 Автообновление приложения — **M**
- `electron-updater` + GitHub Releases (electron-builder уже настроен,
  `publish` добавить в `electron-builder.yml`). Проверка при старте, тихая
  загрузка, баннер «Restart to update».

### 3.6 Бэкап/восстановление — **M, после 3.4**
- Экспорт списка модов с CF-идентификаторами (fingerprint-матчинг уже есть) —
  восстановление библиотеки на новой машине скачиванием из CF.

### 3.7 Кнопка «Запустить игру» — **S, приятная мелочь**
- Найти установку TS4 (реестр/стандартные пути), кнопка в сайдбаре.
